1. IAM (Identity & Access Management)

IAM là gì?

IAM là dịch vụ quản lý danh tính và quyền truy cập AWS. Mọi thao tác với AWS API đều phải qua IAM authentication + authorization. IAM không phải là service-specific — nó áp dụng cho toàn bộ tài khoản AWS.

IAM Components

👤 User

Một người/vật thực thể. Có long-term credentials (password + access key). Khuyến nghị: 1 user = 1 người thật.

👥 Group

Tập hợp users. Gán policy cho group thay vì từng user. Quản lý dễ hơn, ít trùng lặp.

🤖 Role

Không gắn với user cụ thể. Được assume bởi users, services (EC2, Lambda), hoặc AWS accounts khác. Có temporary credentials (STS).

📜 Policy

JSON document định nghĩa quyền (Allow/Deny) trên các resource. Gán vào User, Group, hoặc Role.

IAM Policy — cấu trúc JSON

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject"
      ],
      "Resource": "arn:aws:s3:::my-app-bucket/uploads/*"
    },
    {
      "Effect": "Deny",
      "Action": "s3:DeleteObject",
      "Resource": "*"
    }
  ]
}

Least Privilege — nguyên tắc vàng

Chỉ cấp quyền tối thiểu cần thiết. Dùng AWS Managed Policies khi bắt đầu, sau đó chuyển sang Customer Managed Policies chi tiết hơn. Tránh dùng "Action": "*" và "Resource": "*" cùng lúc.

IAM Roles cho EC2

// Khi EC2 cần truy cập S3 — không bao giờ đặt access key trong code
// Bước 1: Tạo IAM Role với policy S3 access
// Bước 2: Gán Role vào EC2 Instance Profile
// Bước 3: Code dùng AWS SDK — tự động lấy credentials từ Instance Metadata

// SDK sẽ tự động gọi http://169.254.169.254/latest/meta-data/iam/security-credentials/
const { S3Client } = require('@aws-sdk/client-s3');
const s3 = new S3Client({ region: 'ap-southeast-1' });  // Không cần credentials!

IAM Policy Evaluation Logic

Request → Explicit Deny? → YES → DENY ✗
↓ NO
Allow? → YES → ALLOW ✓
↓ NO
Implicit Deny ✗ (mặc định)

Quy tắc: Explicit Deny luôn thắng mọi Allow. Nếu không có Allow nào match → implicit deny.

STS — Assume Role

// User A (account 111) assume Role ở account 222
aws sts assume-role \
  --role-arn "arn:aws:iam::222:role/CrossAccountRole" \
  --role-session-name "my-session"

// Output: AccessKeyId, SecretAccessKey, SessionToken (tạm thời, mặc định 1h)

IAM Best Practices

  • Không dùng root account — tạo admin user với MFA, khóa root access key
  • MFA bắt buộc cho users có quyền cao (admin, billing)
  • Rotate access key định kỳ (90 ngày) — dùng 2 keys để zero-downtime rotation
  • IAM Access Analyzer — phát hiện resource được share public ra ngoài account
  • Service Control Policies (SCP) — Organization-level permission boundary
  • Permissions Boundary — giới hạn maximum permission cho IAM entities
2. VPC (Virtual Private Cloud) & Networking

VPC là gì?

VPC là mạng ảo riêng trong AWS — logically isolated network trong tài khoản của bạn. Bạn tự định nghĩa IP range, subnets, route tables, gateways.

VPC Architecture cơ bản

Internet ─→ Internet Gateway (IGW) ─→ Public Subnet ─→ EC2
│
└─→ NAT Gateway ─→ Private Subnet ─→ EC2/DB
│
VPC Peering / VPN / Direct Connect

CIDR & Subnets

// VPC — 1 region, nhiều Availability Zones
VPC CIDR: 10.0.0.0/16 (65536 địa chỉ — AWS reserved 5 đầu mỗi subnet)

// Public subnet — có route đến IGW
Public Subnet  10.0.1.0/24  (AZ: ap-southeast-1a) — Web servers, Load Balancers
Public Subnet  10.0.2.0/24  (AZ: ap-southeast-1b)

// Private subnet — không có route đến IGW, ra internet qua NAT
Private Subnet 10.0.3.0/24  (AZ: ap-southeast-1a) — App servers
Private Subnet 10.0.4.0/24  (AZ: ap-southeast-1b)

// Database subnet — private, chỉ app servers access
DB Subnet      10.0.5.0/24  (AZ: ap-southeast-1a) — RDS, ElastiCache
DB Subnet      10.0.6.0/24  (AZ: ap-southeast-1b)

Security Groups vs NACL

🔒 Security Group (Stateful)

  • Stateful — allow inbound → tự động allow outbound response
  • Chỉ có Allow rules (không Deny)
  • Attach vào ENI (EC2, RDS, ELB)
  • Reference SG khác: sg-xxx
  • Default: block all inbound, allow all outbound

📋 NACL (Stateless)

  • Stateless — phải define cả inbound + outbound rules
  • Có Allow + Deny rules (đánh số, số nhỏ ưu tiên hơn)
  • Attach vào Subnet (affect all instances trong subnet)
  • Chỉ reference IP/CIDR, không reference SG
  • Dùng để deny list (block IP cụ thể)

NAT Gateway vs NAT Instance

// NAT Gateway — managed service
// - AWS quản lý, auto multi-AZ, bandwidth up to 45 Gbps
// - Không cần patch, không là Bastion Host
// - Giá theo giờ + data processed (~$0.045/h + $0.045/GB)
// - Mỗi AZ cần 1 NAT Gateway riêng

// NAT Instance — EC2 tự quản
// - Bạn tự setup iptables / NAT
// - Cần patch OS, quản lý instance
// - Có thể làm Bastion Host (SSH)
// - Rẻ hơn nếu traffic thấp

VPC Endpoints

// Interface Endpoint (PrivateLink) — dùng cho services có ENI
// - S3, DynamoDB có Gateway Endpoint (free, dùng route table)
// - Còn lại: SSM, ECR, Lambda, SQS, Kinesis → Interface Endpoint ($)

// Gateway Endpoint — free, dùng Prefix List trong route table
// - Chỉ có S3 và DynamoDB
// - Không cần NAT, không cần IGW
// - Route table: 10.0.0.0/16 → local, pl-xxxxx (S3) → vpce-xxxx

VPC Peering & Transit Gateway

🔗 VPC Peering

Kết nối 2 VPC (cùng hoặc khác account). Không transitive — A→B và B→C không cho A→C. Route table entries thủ công. Cross-region OK.

🚇 Transit Gateway

Hub-and-spoke — 1 TG kết nối N VPC, VPN, Direct Connect. Transitive routing. Có route tables riêng. Pay per attachment + GB processed.

VPC Flow Logs

// Ghi lại tất cả traffic trong VPC/Subnet/ENI

// Dùng để troubleshoot kết nối, security analysis, network monitoring

// Format: version account-id eni-id src-addr dst-addr src-port dst-port protocol

3. EC2 & Auto Scaling

EC2 Instance Types & Families

⚡ General Purpose (T3, M7g)

Web servers, small DB, dev/test. T3 burstable (CPU credits). M7g: Graviton3 ARM, 20% rẻ hơn Intel.

🔬 Compute Optimized (C7g)

Batch processing, gaming, HPC, CI/CD runners. Giá/vCPU thấp nhất. Graviton3 cho performance cao.

📦 Memory Optimized (R7g, X2iedn)

In-memory caches (Redis), large DB, real-time analytics. X2iedn: up to 4TB RAM/instance.

exec > /var/log/user-data.log 2>&1  # log tất cả output

# ECR login — cần IAM Role

  docker login --username AWS --password-stdin \

docker run -d -p 80:3000 --name my-app \

EC2 Best Practices

  • Dùng IAM Role cho EC2 — không bao giờ nhúng access key vào instance
  • IMDSv2 bắt buộc — set MetadataOptions HttpTokens=required
  • SSM Session Manager thay vì SSH — không cần bastion, không cần security group port 22
  • Spot Instances cho workload chịu được interrupt (batch, CI/CD, stateless workers) — tiết kiệm 70-90%
  • Placement Groups: Cluster (low-latency, 10 Gbps), Spread (HA, max 7 instances/AZ), Partition (HDFS, Cassandra)
  • Auto Recovery: CloudWatch alarm → auto-recover instance nếu health check fail
4. Lambda & Serverless

Lambda là gì?

Function-as-a-Service (FaaS) — chạy code không cần quản lý server. AWS quản lý infrastructure, auto-scale từ 0 đến hàng ngàn concurrent executions. Chỉ trả tiền khi code chạy (per request + compute duration).

Lambda Execution Model

Event Source (S3, SQS, API GW, DynamoDB Streams, EventBridge, ...)
↓
Lambda Service → Cold Start (nếu chưa có warm container)
↓
Execution Environment (sandbox)
↓
Handler được gọi với event + context
├── /tmp: 512 MB – 10 GB (ephemeral storage)
└── environment variables (4 KB max, encrypted với KMS)

Lambda với API Gateway (REST API)

// handler.mjs
import { DynamoDBClient } from '@aws-sdk/client-dynamodb';
import { DynamoDBDocumentClient, PutCommand, GetCommand } from '@aws-sdk/lib-dynamodb';

const ddb = DynamoDBDocumentClient.from(new DynamoDBClient({}));

export const handler = async (event) => {
  const headers = {
    'Content-Type': 'application/json',
    'Access-Control-Allow-Origin': '*',   // CORS
  };

  try {
    switch (event.httpMethod) {
      case 'GET': {
        const { id } = event.pathParameters || {};
        if (!id) return { statusCode: 400, headers, body: JSON.stringify({ error: 'Missing id' }) };

        const { Item } = await ddb.send(new GetCommand({
          TableName: process.env.TABLE_NAME,
          Key: { pk: id },
        }));
        return {
          statusCode: Item ? 200 : 404,
          headers,
          body: JSON.stringify(Item ?? { error: 'Not found' }),
        };
      }

      case 'POST': {
        const body = JSON.parse(event.body || '{}');
        const item = { pk: crypto.randomUUID(), ...body, createdAt: new Date().toISOString() };
        await ddb.send(new PutCommand({ TableName: process.env.TABLE_NAME, Item: item }));
        return { statusCode: 201, headers, body: JSON.stringify(item) };
      }

      default:
        return { statusCode: 405, headers, body: JSON.stringify({ error: 'Method not allowed' }) };
    }
  } catch (err) {
    console.error('Error:', err);
    return { statusCode: 500, headers, body: JSON.stringify({ error: 'Internal server error' }) };
  }
};

Event Source Mappings

// Lambda poll SQS / DynamoDB Streams / Kinesis — không cần code poll

// SQS — batching & partial batch response
export const handler = async (event) => {
  const failedIds = [];
  for (const record of event.Records) {
    try {
      await processMessage(JSON.parse(record.body));
    } catch (err) {
      console.error('Failed:', record.messageId, err);
      failedIds.push(record.messageId);
    }
  }
  // Report batch item failures — chỉ những message failed mới xuất hiện lại
  return { batchItemFailures: failedIds.map(id => ({ itemIdentifier: id })) };
};

// Cấu hình mapping:
// - Batch size: 1–10 (SQS), tối đa 10000 (Kinesis/DynamoDB Streams)
// - Maximum batching window: 0–300s
// - Concurrency: Reserved concurrency (tránh throttling)
// - DLQ: cho event không xử lý được sau max retries

Lambda Power Tuning

// Memory: 128 MB – 10,240 MB (1 MB steps)
// CPU tỉ lệ với memory — 1769 MB = 1 vCPU, 3538 MB = 2 vCPU, ...
// Network bandwidth cũng tăng theo memory

// Cost optimization: tăng memory → giảm duration
// Test: 128 MB → 3s (cost 128 × 3 = 384) vs 1024 MB → 0.4s (cost 1024 × 0.4 = 409)

// → Dùng AWS Lambda Power Tuning (Step Functions state machine) để tìm optimal memory
// → Thường optimal ở 1024–2048 MB cho Node.js/Python, 2048+ cho Java

Lambda Best Practices

  • Cold Start: Java/.NET cold start ~1-5s, Node.js/Python/Go ~100-300ms. Dùng Provisioned Concurrency cho latency-critical apps
  • Execution Timeout: tối đa 15 ph (900s). Workflow >15 ph → Step Functions + Lambda
  • Environment Variables: dùng cho config (stage, table name). Secrets → Secrets Manager, Parameter Store (SecureString)
  • Stateless: không lưu state trong memory giữa các invocations. /tmp tồn tại giữa các warm starts
  • VPC Lambda: cần ENI trong VPC → cold start lâu hơn, tốn IP. Chỉ đặt Lambda trong VPC khi cần truy cập RDS/ElastiCache
  • Dead Letter Queue (DLQ): bắt event failed sau max retries. Dùng SQS hoặc SNS
  • Reserved Concurrency: tránh một function "ăn" hết account concurrency limit (1000/region)
5. ECS & Container Orchestration

ECS là gì?

Amazon Elastic Container Service — orchestration cho Docker containers. Có 2 launch types: Fargate (serverless — không quản lý server) và EC2 (tự quản cluster).

ECS Architecture

┌─→ Target Group ─→ Service ─→ Task (Fargate/EC2)
ALB / NLB ────┤
└─→ Target Group ─→ Service ─→ Task
│
Task Definition
├── container image (ECR)
├── port mapping
├── env vars / secrets
├── resource (CPU, memory)
└── IAM Task Role

Task Definition (ví dụ)

// task-definition.json — JSON format
{
  "family": "my-app",
  "taskRoleArn": "arn:aws:iam::xxx:role/ecsTaskRole",
  "executionRoleArn": "arn:aws:iam::xxx:role/ecsExecutionRole",
  "networkMode": "awsvpc",        // Fargate bắt buộc
  "requiresCompatibilities": ["FARGATE"],
  "cpu": "512",                   // 0.5 vCPU (256=0.25, 512=0.5, 1024=1, 2048=2, 4096=4)
  "memory": "1024",               // MB
  "containerDefinitions": [{
    "name": "app",
    "image": "xxx.dkr.ecr.ap-southeast-1.amazonaws.com/my-app:latest",
    "portMappings": [{ "containerPort": 3000, "protocol": "tcp" }],
    "environment": [
      { "name": "NODE_ENV", "value": "production" }
    ],
    "secrets": [
      { "name": "DB_PASSWORD", "valueFrom": "arn:aws:ssm:...:parameter/prod/db/password" }
    ],
    "logConfiguration": {
      "logDriver": "awslogs",
      "options": {
        "awslogs-group": "/ecs/my-app",
        "awslogs-region": "ap-southeast-1",
        "awslogs-stream-prefix": "ecs"
      }
    },
    "healthCheck": {
      "command": ["CMD-SHELL", "curl -f http://localhost:3000/health || exit 1"],
      "interval": 30,
      "timeout": 5,
      "retries": 3,
      "startPeriod": 60
    }
  }]
}

ECS Service với ALB

// Service = long-running tasks (web app, worker)
// - Số lượng desired tasks

// - Auto-recovery: ECS restart task nếu health check fail

    "minimumHealthyPercent": 100
  }'

// deploymentCircuitBreaker — tự động rollback nếu deployment thất bại

ECS vs EKS vs Lambda

🐳 ECS (Fargate)

Serverless container. AWS quản lý control plane. Không cần quản lý cluster nodes. Tích hợp sâu AWS (ALB, CloudWatch, IAM). Đơn giản nhất.

☸️ EKS (Kubernetes)

Managed K8s — chuẩn CNCF. Portable (chạy on-prem, multi-cloud). Phức tạp hơn nhưng flexible hơn. Cần quản lý worker nodes (self-managed hoặc Fargate).

⚡ Lambda

FaaS — event-driven. Tối đa 15 ph execution. Cold start. Phù hợp: API, event processing, cron jobs. Không phù hợp: long-running, WebSocket, large containers.

6. S3 (Simple Storage Service)

S3 là gì?

S3 là object storage — lưu trữ unlimited objects (0 byte – 5 TB). 99.999999999% durability (11 9's). Dữ liệu replicated qua ít nhất 3 AZ trong region.

S3 Storage Classes

⚡ S3 Standard

Frequent access, low latency. 99.99% availability. $0.023/GB. Cho web app, big data analytics.

📉 S3 Intelligent-Tiering

Tự động di chuyển objects giữa tiers dựa trên access pattern. $0.0025/1000 objects monitoring fee. Cho data access pattern khó đoán.

❄️ S3 Glacier (Instant/Flexible/Deep Archive)

Archive — rẻ nhất $0.001/GB. Deep Archive: restore 12h. Cho backup, compliance.

🗄️ S3 One Zone-IA

Chỉ 1 AZ, rẻ hơn Standard-IA 20%. Cho non-critical / reproducible data.

S3 Bucket Policy & ACL

// Bucket Policy — cho phép public read (static website)

  </Expiration>
</Rule>

// CloudFront trước mặt S3 — HTTPS, caching, custom domain, WAF, global
// Origin Access Control (OAC) — chỉ CloudFront mới được truy cập S3

S3 Best Practices

  • Prefix cho performance: S3 hỗ trợ 5500 GET/3500 PUT requests/s mỗi prefix. Nếu cần hơn → dùng nhiều prefixes (e.g. /user/123/ vs /user/456/)
  • Multipart Upload: cho file >100 MB — parallel upload parts, retry từng part
  • Transfer Acceleration: dùng AWS edge locations cho upload từ xa (tốn phí)
  • Object Lock: WORM (Write Once Read Many) — compliance, legal hold
  • Replication: CRR (cross-region) cho disaster recovery, SRR (same-region) cho log aggregation
7. RDS & DynamoDB

RDS — Relational Databases

Managed DB: Aurora, PostgreSQL, MySQL, MariaDB, SQL Server, Oracle. AWS quản lý: OS patching, backup, replication, failover.

RDS Multi-AZ & Read Replicas

Multi-AZ (HA):
Primary (AZ-a) ↔ Standby (AZ-b) — synchronous replication
↓ auto failover (DNS CNAME switch, ~60-120s)
CNAME luôn trỏ về primary

Read Replicas (performance):
Primary → Read Replica 1 (AZ-b) — async replication
→ Read Replica 2 (region 2) — cross-region
→ Read Replica 3 (region 3) — DR 
// Tạo read replica — zero downtime cho primary
aws rds create-db-instance-read-replica \
  --db-instance-identifier mydb-replica \
  --source-db-instance-identifier mydb \
  --region ap-southeast-1

// Promote to standalone (cho DR / migration)
aws rds promote-read-replica --db-instance-identifier mydb-replica

RDS Backup & Restore

// Automated backup — mặc định 7 ngày (tối đa 35)

DynamoDB — NoSQL Key-Value & Document

Managed NoSQL — single-digit millisecond latency ở bất kỳ scale nào. Auto-scaling, multi-AZ, DAX (in-memory cache).

DynamoDB Table Design

// Single Table Design — 1 bảng cho nhiều entity types
// Partition Key (PK) + Sort Key (SK) + Global Secondary Index (GSI)

// Ví dụ: E-commerce app
// PK              SK                      Data
// USER#alice      PROFILE                 { name:"Alice", email, ... }
// USER#alice      ORDER#2024-01-01#001    { total: 50, items: [...] }
// USER#bob        PROFILE                 { name:"Bob", ... }
// PRODUCT#kindle  META                    { title:"Kindle", price:99, ... }

// GSI1: PK=SK, SK=GSI1PK — query theo pattern khác
// GSI1PK = ORDER#2024-01-01#001  → Query đơn hàng theo order ID
// GSI2PK = STATUS#shipped         → Query all shipped orders

DynamoDB Operations

// Write
await ddb.send(new PutCommand({
  TableName: 'Orders',
  Item: {
    pk: 'USER#alice',
    sk: 'ORDER#001',
    total: 50,
    status: 'PENDING',
    items: [{ productId: 'kindle', qty: 1, price: 50 }],
  },
  ConditionExpression: 'attribute_not_exists(pk)',  // Chỉ tạo nếu chưa tồn tại
}));

// Read — 2 loại: GetItem (1 item theo PK+SK), Query (nhiều items)
const { Items } = await ddb.send(new QueryCommand({
  TableName: 'Orders',
  KeyConditionExpression: 'pk = :pk AND begins_with(sk, :prefix)',
  ExpressionAttributeValues: {
    ':pk': 'USER#alice',
    ':prefix': 'ORDER#',
  },
  Limit: 10,
  ScanIndexForward: false,  // DESC theo SK
}));

// Transaction — ACID cross items
await ddb.send(new TransactWriteCommand({
  TransactItems: [
    { Put: { TableName: 'Orders', Item: order } },
    { Update: {
        TableName: 'Products',
        Key: { pk: 'PRODUCT#kindle', sk: 'META' },
        UpdateExpression: 'SET stock = stock - :qty',
        ConditionExpression: 'stock >= :qty',
      }
    }
  ]
}));

DynamoDB Streams & TTL

// Streams — ghi lại thay đổi (INSERT, MODIFY, REMOVE) trong 24h
// Trigger Lambda để: sync sang OpenSearch, update cache, analytics

// TTL (Time To Live) — tự động xóa item sau timestamp
// - Dùng cho session, event, log expiration

RDS vs DynamoDB — chọn cái nào?

🗄️ RDS (SQL)

  • Dữ liệu có quan hệ (JOIN, FK)
  • Complex queries, aggregations, transactions
  • Schema fixed, cần migration
  • Ví dụ: ERP, CRM, accounting

📊 DynamoDB (NoSQL)

  • Key-value access pattern, high scale
  • Single-digit ms ở mọi scale
  • Schema-less, denormalized
  • Ví dụ: user session, shopping cart, IoT, gaming leaderboard

      assignPublicIp: true,

Rẻ nhất. Daily backup S3 → Glacier. Khi disaster: restore to new region. Phù hợp: non-critical systems.

10. Bastion & Jump Host

Bastion Host là gì?

Bastion Host (Jump Host / Jump Box) là máy chủ hardened đặt ở public subnet, là cổng vào duy nhất (single entry point) để SSH/RDP vào các máy trong private subnet — nơi không có public IP.

Internet ──SSH:22──▶ [ BASTION ] ──SSH──▶ [ App 10.0.1.10 ]
(chỉ từ IP của bạn) Public subnet │ [ DB 10.0.1.20 ]
Private subnet (không public IP)

Bastion vs Jump Host

Hai thuật ngữ dùng thay thế được. Bastion nhấn mạnh tính bảo mật (hardened, 2FA, audit), Jump Host nhấn mạnh chức năng trung chuyển.

Vì sao cần?

  • Private subnet không có public IP — không SSH trực tiếp từ internet được
  • Giảm attack surface — chỉ 1 máy lộ ra internet, không phải tất cả
  • Kiểm soát tập trung — 1 điểm duy nhất để log, audit, giám sát truy cập
  • Security Group gọn — private instance chỉ mở port 22 từ bastion SG
  • Compliance — biết chính xác ai vào hệ thống lúc nào

Kiến trúc + Security Group chuẩn

VPC (10.0.0.0/16)
├── Public Subnet 10.0.1.0/24 → IGW + Bastion (EIP) + NAT Gateway
└── Private Subnet 10.0.2.0/24 → App + DB

Bastion-SG (inbound): SSH 22 ← Chỉ IP công ty/VPn (VD 203.0.113.5/32)
App-SG (inbound):     SSH 22 ← source = Bastion-SG (không phải 0.0.0.0/0!)
DB-SG (inbound):      MySQL 3306 ← source = App-SG

Nguyên tắc vàng: private instance KHÔNG BAO GIỜ mở port 22 cho 0.0.0.0/0 — chỉ mở cho security group của bastion.

3 cách SSH qua Bastion

1. SSH Agent Forwarding (tiện, rủi ro hơn)

ssh-add ~/.ssh/my-key.pem          # thêm key vào agent (local)
ssh -A ec2-user@bastion-ip        # -A = agent forwarding
ssh ec2-user@10.0.2.10            # từ bastion SSH tiếp (mượn key local)

⚠️ Mọi tiến trình trên bastion có thể mượn key của bạn — chỉ dùng khi bastion cực tin cậy, thêm ssh-add -t 3600 (key hết hạn sau 1h).

2. ProxyJump — an toàn nhất (khuyến nghị)

Key không đặt trên bastion, máy local tự đi qua bastion tới đích.

# 1 lần
ssh -J ec2-user@bastion-ip ec2-user@10.0.2.10

# ~/.ssh/config — dùng lâu dài
Host bastion
    HostName 203.0.113.5
    User ec2-user
    IdentityFile ~/.ssh/aws-bastion.pem

Host 10.0.2.*
    User ec2-user
    IdentityFile ~/.ssh/aws-app.pem
    ProxyJump bastion
# Sau đó chỉ cần: ssh 10.0.2.10

3. SCP / SFTP qua bastion

scp -o ProxyJump=ec2-user@bastion-ip ./file.txt ec2-user@10.0.2.10:/tmp/
sftp -J ec2-user@bastion-ip ec2-user@10.0.2.10

Bảo mật — Checklist

  • SG chỉ mở SSH từ IP của bạn — không bao giờ 0.0.0.0/0
  • Dùng key riêng cho bastion, tắt password auth (PasswordAuthentication no)
  • Không đặt private key lên bastion — dùng ProxyJump / SSM
  • Cài fail2ban chống brute-force + giới hạn MaxAuthTries
  • MFA cho SSH (Google Authenticator PAM)
  • Log SSH → CloudWatch Logs / S3 để audit
  • Patch định kỳ bằng SSM Patch Manager
  • Bastion chỉ làm đúng 1 việc — không cài tool thừa

Thay thế hiện đại: SSM Session Manager (khuyến nghị)

SSH vào private instance không cần bastion, không mở port 22, không public IP. Dùng IAM thay vì SSH keys, log đầy đủ, tích hợp MFA, chi phí 0$.

# Điều kiện: SSM agent + IAM role (AmazonSSMManagedInstanceCore) + route/NAT hoặc VPC Endpoint
aws ssm start-session --target i-xxxxx

# Port forward qua SSM — truy cập RDS private không cần bastion
aws ssm start-session --target i-xxxxx \
  --document-name AWS-StartPortForwardingSession \
  --parameters '{"portNumber":["3306"],"localPortNumber":["8080"]}'
mysql -h localhost -P 8080 -u admin -p

Bastion vs NAT Gateway — đừng nhầm!

🛡️ Bastion Host

🌐 NAT Gateway

Outbound — cho private instances đi ra internet. Không cho ai vào từ ngoài.

Troubleshooting nhanh

  • Connection timed out → SG chưa mở port 22 / sai IP → kiểm tra inbound rule bastion SG
  • Permission denied (publickey) → sai key hoặc permission file key (cần 600)
  • SSH vào private bị treo → App-SG chưa cho source = Bastion-SG; thử ssh -vvv
  • Agent forwarding không chạy → eval $(ssh-agent); kiểm tra ssh-add -l
  • 429 rate limit khi SSH → brute-force → bật fail2ban, giới hạn IP SG

Câu hỏi phỏng vấn / exam nhanh

  • Bastion vs NAT? Bastion = inbound (vào), NAT = outbound (ra)
  • Cách vào private subnet an toàn nhất? 1) SSM Session Manager, 2) ProxyJump qua bastion, 3) Agent Forwarding (rủi ro nhất)
  • SG private instance mở port 22 cho ai? Chỉ cho security group của bastion — không bao giờ 0.0.0.0/0
  • Bastion là single point of failure? Đúng — giải pháp: 2 bastion 2 AZ + Route 53 health check, hoặc Auto Scaling, hoặc bỏ hẳn dùng SSM
  • Exam SAA thường chọn đáp án nào? SSM Session Manager thay bastion (an toàn, free, audit tốt)
