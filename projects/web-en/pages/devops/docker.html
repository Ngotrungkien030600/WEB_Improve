1. Image vs Container

Khái niệm (Concept)

Image (Ảnh container): A read-only template that contains the application and everything it needs to run — code, runtime, libraries, environment variables, config files. (Một bản mẫu chỉ-đọc chứa ứng dụng và mọi thứ cần để chạy — code, runtime, thư viện, biến môi trường, cấu hình.)

Container (Container): A running instance of an image — an isolated process with its own filesystem, network, and resources. (Một instance đang chạy của image — một tiến trình cô lập với filesystem, network và tài nguyên riêng.)

Dockerfile ──build──▶ Image ──run──▶ Container(s)
[template, read-only, shareable]    [process, writable, isolated]

Bảng so sánh (Comparison)

ImageContainer
Template read-only (bản mẫu chỉ-đọc)Instance đang chạy (instance running)
Giống class trong OOPGiống object được tạo từ class
Push/pull từ registry (Docker Hub)Start, stop, restart, delete
Có thể share giữa nhiều máyChạy trên máy có Docker engine

Container vs VM (Tại sao container nhẹ hơn?)

  • VM: Mỗi máy ảo chứa cả OS (Guest OS) — nặng, khởi động chậm (phút).
  • Container: Chia sẻ kernel của host OS — chỉ chứa app + dependencies — nhẹ, khởi động trong (giây).
  • Container dùng namespace (cô lập tiến trình/filesystem/network) và cgroups (giới hạn CPU/RAM).

Lệnh cơ bản (Basic Commands)

docker pull nginx:alpine        # Tải image từ registry
docker images                   # Liệt kê images
docker run -d -p 8080:80 --name web nginx
docker ps                       # Liệt kê containers đang chạy
docker ps -a                    # Tất cả containers (kể cả đã dừng)
docker logs web                 # Xem log
docker exec -it web sh          # Vào bên trong container
docker stop web && docker rm web
docker rmi nginx:alpine         # Xóa image
2. Dockerfile

Dockerfile là gì?

A text file with instructions that defines how to build an image. (Một file văn bản chứa các chỉ dẫn định nghĩa cách build một image.)

# Ví dụ: Dockerfile cho Spring Boot app
FROM eclipse-temurin:17-jdk-alpine   # Base image (runtime)
WORKDIR /app                          # Thư mục làm việc
COPY target/app.jar app.jar           # Copy file vào image
EXPOSE 8080                           # Khai báo cổng lắng nghe
ENTRYPOINT ["java", "-jar", "app.jar"] # Lệnh chạy khi container khởi động

Các chỉ dẫn quan trọng (Key Instructions)

FROM

Chọn base image — bắt buộc phải có đầu tiên. Nên dùng bản alpine (nhẹ).

RUN

Chạy lệnh lúc build (cài package, compile). Mỗi RUN tạo một layer.

COPY / ADD

Copy file từ host vào image. ADD còn hỗ trợ URL/auto-extract — ưu tiên COPY.

ENV / ARG

ENV: biến môi trường (tồn tại lúc runtime). ARG: biến chỉ dùng lúc build.

CMD / ENTRYPOINT

Đều khai báo lệnh chạy. CMD bị ghi đè khi chạy, ENTRYPOINT thì không. Thường kết hợp cả hai.

EXPOSE

Chỉ là documentation — cổng thực sự mở khi dùng -p lúc run.

Layer & Cache (Lớp và bộ nhớ đệm)

Mỗi lệnh Dockerfile tạo một layer. Docker cache từng layer — nếu layer không đổi, Docker tái dùng kết quả. Thứ tự quan trọng: đặt các bước ít thay đổi (cài dependencies) lên trước để tận dụng cache.

# Tối ưu: copy package file trước, cài deps, rồi mới copy source
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci                     # Chỉ build lại khi package thay đổi
COPY . .
RUN npm run build
CMD ["npm", "start"]
3. Docker Compose

Compose là gì?

A tool to define and run multi-container applications with a single YAML file. (Công cụ định nghĩa và chạy ứng dụng nhiều container bằng một file YAML duy nhất.)

# docker-compose.yml
version: '3.8'
services:
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://db:5432/mydb
    depends_on:
      - db
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: admin
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: mydb
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:

Lệnh Compose (Compose Commands)

docker compose up -d        # Build + start tất cả services
docker compose down         # Stop + xóa containers (giữ volume)
docker compose down -v      # Xóa luôn volumes
docker compose ps           # Xem trạng thái
docker compose logs -f      # Xem log tất cả services
docker compose exec app sh  # Chạy lệnh trong service app

Lưu ý (Notes)

  • Các service trong cùng compose tự động nằm chung 1 network — gọi nhau qua tên service (vd: db:5432).
  • depends_on chỉ đảm bảo thứ tự khởi động, không đợi service sẵn sàng — cần healthcheck nếu muốn chờ.
  • Biến môi trường có thể ngoại suy qua file .env.
4. Volume & Persistent Data

Tại sao cần volume?

Container filesystem là tạm thời — dữ liệu mất khi container bị xóa. Volumes lưu dữ liệu ở host, sống sót qua vòng đời container. (Container filesystem is ephemeral — data is lost when the container is removed. Volumes store data on the host and survive the container lifecycle.)

Container (writable layer — mất khi xóa container)
└── Volume (lưu trên host — bền vững) / Bind Mount (thư mục host)

3 loại lưu trữ (3 Storage Types)

📦 Named Volume

Quản lý bởi Docker (/var/lib/docker/volumes). Khuyến nghị cho DB, dữ liệu app.

🔗 Bind Mount

Trỏ trực tiếp tới thư mục host — thường dùng cho dev (hot-reload code).

💾 tmpfs

Lưu trong RAM — nhanh nhưng mất khi container dừng. Dùng cho cache.

# Named volume
docker run -d -v pgdata:/var/lib/postgresql/data postgres

# Bind mount (dev) — thư mục host:thư mục container
docker run -d -v $(pwd)/src:/app/src node:20

Lệnh volume (Volume Commands)

docker volume ls
docker volume create mydata
docker volume inspect mydata
docker volume rm mydata
5. Network

Các loại network driver

bridge (mặc định)

Mỗi container có IP riêng trong subnet nội bộ. Container cùng bridge giao tiếp được với nhau qua IP/tên.

host

Container dùng thẳng network của host — không có NAT. Hiệu năng cao, nhưng không cô lập port.

none

Không có network — cô lập hoàn toàn. Dùng cho tasks nhạy cảm.

overlay

Dùng cho multi-host (Docker Swarm / K8s) — container ở máy khác nhau vẫn nói chuyện được.

Lệnh network (Network Commands)

docker network ls
docker network create mynet
docker run -d --network mynet nginx
docker network inspect mynet

Port mapping (Ánh xạ cổng)

# -p host_port:container_port
docker run -d -p 8080:80 nginx   # Truy cập localhost:8080 → container:80
docker run -d -p 3000:3000 myapp
docker run -d -p 80:80 -p 443:443 nginx   # Nhiều cổng
6. Multi-stage Build

Tại sao multi-stage?

Build app cần đầy đủ toolchain (JDK, npm, compilers) nhưng image chạy chỉ cần runtime. Multi-stage build tách build và runtime thành 2 stage — image cuối nhỏ gọn, an toàn hơn. (Why multi-stage? Building needs the full toolchain, but the runtime image only needs the runtime. Multi-stage separates build and runtime into two stages — the final image is smaller and more secure.)

# Stage 1: BUILD — đầy đủ toolchain
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: RUN — chỉ runtime
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Ví dụ Java

# Stage 1: compile
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn package -DskipTests

# Stage 2: runtime chỉ với JRE
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
7. Best Practices

Quy tắc vàng (Golden Rules)

✅ Nên làm

  • Dùng base image alpine/nhỏ gọn
  • Multi-stage build để giảm kích thước
  • Sắp xếp lệnh ít thay đổi trước để tận dụng cache
  • Chạy container với user non-root
  • Khai báo HEALTHCHECK
  • Dùng .dockerignore loại bỏ file không cần thiết

❌ Tránh

  • Dùng tag latest mơ hồ — pin version cụ thể
  • Chạy container với root
  • Chứa secrets (password/keys) trong image
  • Một container chứa nhiều process
  • Dùng ADD khi chỉ cần COPY

HEALTHCHECK & .dockerignore

HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD curl -f http://localhost:8080/actuator/health || exit 1
# .dockerignore
node_modules
.git
target
dist
*.log
8. Câu hỏi phỏng vấn (Interview Questions)

❓ Image vs Container khác gì?

Image là template read-only, container là instance đang chạy. Image có thể build/share, container có lifecycle (start/stop).

❓ Container khác VM thế nào?

VM có Guest OS riêng (heavy), container share kernel host — nhẹ hơn, khởi động nhanh hơn, dùng namespace + cgroups để cô lập.

❓ Dockerfile layer là gì?

Mỗi instruction tạo 1 layer bất biến. Docker cache từng layer để build nhanh hơn khi không đổi.

❓ CMD vs ENTRYPOINT?

CMD có thể bị ghi đè khi run, ENTRYPOINT không. Thường ENTRYPOINT cố định lệnh, CMD cung cấp default args.

❓ Làm sao giữ dữ liệu khi container xóa?

Dùng volume (named volume / bind mount) — dữ liệu nằm trên host, không phụ thuộc vòng đời container.

❓ Multi-stage build lợi ích gì?

Image cuối chỉ chứa runtime, không chứa toolchain build — nhỏ hơn, ít bề mặt tấn công hơn.
