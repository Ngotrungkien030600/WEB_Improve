1. Tổng quan & Kiến trúc (Overview & Architecture)

Kubernetes (K8s) là gì?

An open-source container orchestration platform that automates deployment, scaling, and management of containerized applications. (Nền tảng điều phối container mã nguồn mở — tự động hóa triển khai, mở rộng và quản lý ứng dụng containerized.)

┌──────────────── Control Plane (Master) ────────────────┐
│ API Server ─ etcd ─ Scheduler ─ Controller Manager │
└──────────────────────────┬─────────────────────────────┘
│
┌────────── Worker Node 1 ─┴──── Worker Node 2 ─┐
│ kubelet │ kube-proxy │ Pods (containers) │
└────────────────────────────────────────────────┘

Control Plane vs Worker Nodes

🧠 Control Plane (Master)

  • API Server: cửa ngõ duy nhất — mọi thao tác (kubectl) đi qua đây
  • etcd: kho lưu trạng thái key-value (source of truth)
  • Scheduler: quyết định pod chạy trên node nào
  • Controller Manager: giữ trạng thái mong muốn (desired state)

⚙️ Worker Node

  • kubelet: agent chạy trên node, quản lý pods
  • kube-proxy: xử lý network rules, load balancing
  • Container Runtime: Docker/containerd — chạy containers
  • Pods: đơn vị triển khai nhỏ nhất

Nguyên lý khai báo (Declarative Model)

Bạn khai báo desired state (trạng thái mong muốn) trong manifest YAML. Kubernetes liên tục so sánh với trạng thái hiện tại và tự động điều chỉnh. (You declare the desired state in YAML manifests. K8s continuously reconciles the current state to match.)

2. Pod

Pod là gì?

The smallest deployable unit in Kubernetes — a group of one or more containers sharing the same network namespace and storage. (Đơn vị triển khai nhỏ nhất — một nhóm 1 hoặc nhiều container dùng chung network namespace và storage.)

  • Mỗi pod có 1 IP riêng (cluster-internal).
  • Các container trong cùng pod chia sẻ IP, localhost, volumes.
  • Pod là ephemeral — chết là thay pod mới (thường qua Deployment, không tạo pod trực tiếp).
# pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: nginx
spec:
  containers:
    - name: nginx
      image: nginx:alpine
      ports:
        - containerPort: 80

Lệnh pod (Pod Commands)

kubectl apply -f pod.yaml        # Tạo pod
kubectl get pods                 # Xem danh sách
kubectl get pods -o wide         # Xem chi tiết IP, node
kubectl describe pod nginx-pod   # Xem chi tiết + events
kubectl logs nginx-pod           # Xem log
kubectl exec -it nginx-pod -- sh # Vào pod
kubectl delete pod nginx-pod     # Xóa
3. Deployment & ReplicaSet

Deployment là gì?

A higher-level controller that manages ReplicaSets and provides declarative updates, rollback, and scaling. (Controller cấp cao quản lý ReplicaSet — hỗ trợ cập nhật khai báo, rollback và scale.)

# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
        - name: myapp
          image: myapp:1.0
          ports:
            - containerPort: 8080
          resources:
            requests: { cpu: "100m", memory: "128Mi" }
            limits:   { cpu: "500m", memory: "512Mi" }
          readinessProbe:
            httpGet: { path: /actuator/health, port: 8080 }
            initialDelaySeconds: 5
            periodSeconds: 10

Rolling Update & Rollback

# Cập nhật image lên 1.1 (rolling update, không downtime)
kubectl set image deployment/myapp myapp=myapp:1.1

# Hoặc sửa manifest rồi apply lại
kubectl apply -f deployment.yaml

# Rollback nếu lỗi
kubectl rollout undo deployment/myapp

# Xem trạng thái rollout
kubectl rollout status deployment/myapp
kubectl rollout history deployment/myapp
Deployment ──manage──▶ ReplicaSet ──manage──▶ Pods (3 replicas)
[desired state]   [giữ số lượng replica]   [chạy container]

Lưu ý

  • Không sửa trực tiếp pod — luôn qua Deployment để K8s giữ desired state.
  • strategy: mặc định RollingUpdate; có thể đổi maxUnavailable/maxSurge.
4. Service & Ingress

Tại sao cần Service?

Pod có IP thay đổi khi tái tạo. Service cung cấp địa chỉ ổn định + load balancing giữa các pod. (Pods get new IPs when recreated. A Service provides a stable address and load balancing across pods.)

Client → Service (myapp:80, stable IP) → Load balancer → Pod A / Pod B / Pod C

Các loại Service

ClusterIP (mặc định)

IP nội bộ cluster — chỉ truy cập trong cluster. Dùng cho microservices gọi nhau.

NodePort

Mở port cố định trên mỗi node (30000–32767). Truy cập qua nodeIP:port.

LoadBalancer

Tích hợp cloud provider (AWS ELB/GCP LB) — phơi service ra internet.

# service.yaml — ClusterIP cho nội bộ
apiVersion: v1
kind: Service
metadata:
  name: myapp
spec:
  selector:
    app: myapp        # Chọn pod qua label
  ports:
    - port: 80        # Service port
      targetPort: 8080 # Pod port
  type: ClusterIP

Ingress

Quản lý truy cập HTTP/HTTPS từ ngoài vào cluster — routing theo host/path, TLS, rewrite. (Manages external HTTP/HTTPS access — routing by host/path, TLS, rewrites.)

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: myapp-ingress
spec:
  rules:
    - host: api.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: myapp
                port: { number: 80 }
5. ConfigMap & Secret

ConfigMap

Lưu cấu hình không bí mật (config không nhạy cảm) — tách khỏi image để image tái dùng được. (Stores non-sensitive configuration, decoupled from the image.)

apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  APP_ENV: "production"
  LOG_LEVEL: "info"

Secret

Lưu dữ liệu nhạy cảm (password, keys, tokens) — base64-encoded trong manifest. (Stores sensitive data — base64-encoded in the manifest.)

apiVersion: v1
kind: Secret
metadata:
  name: db-secret
type: Opaque
data:
  DB_PASSWORD: c2VjcmV0MTIz   # base64 của "secret123"

Cách dùng trong Pod (Usage)

spec:
  containers:
    - name: myapp
      env:
        - name: APP_ENV
          valueFrom:
            configMapKeyRef: { name: app-config, key: APP_ENV }
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef: { name: db-secret, key: DB_PASSWORD }

Lưu ý bảo mật

  • Secret mặc định chỉ là base64 (không mã hóa thực sự) — bật Encryption at Rest cho etcd.
  • Ưu tiên dùng External Secrets Operator / Vault trong production.
  • Không commit secret thật vào git — dùng kubectl create secret hoặc sealed-secrets.
6. Autoscaling & Resource

Horizontal Pod Autoscaler (HPA)

Tự động tăng/giảm số replica dựa trên CPU/memory metrics hoặc custom metrics. (Automatically scales replica count based on CPU/memory or custom metrics.)

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: myapp-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: myapp
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70

Requests vs Limits

requests

Mức tài nguyên đảm bảo — Scheduler dựa vào đây để xếp pod vào node. Không đạt → bị "giảm chất lượng" (throttle).

limits

Mức tối đa — vượt CPU bị throttle, vượt memory bị OOMKill. Không set limits → container có thể chiếm hết node.

Vertical Pod Autoscaler (VPA) & Cluster Autoscaler

  • VPA: tự chỉnh requests/limits của pod.
  • Cluster Autoscaler: thêm/bớt node trong cloud khi thiếu tài nguyên.
7. Namespace & kubectl

Namespace là gì?

Phân vùng cluster thành các môi trường/logic groups — tách biệt tài nguyên, dễ quản lý RBAC và quota. (Partitions a cluster into logical groups — isolates resources, simplifies RBAC and quotas.)

kubectl get namespaces          # dev, prod, kube-system...
kubectl create namespace dev
kubectl get pods -n dev          # Lọc theo namespace
kubectl config set-context --current --namespace=dev

kubectl thông dụng (Common kubectl)

kubectl get all                  # Xem pods/services/deployments
kubectl get nodes
kubectl describe pod <name>
kubectl logs -f deployment/myapp
kubectl port-forward svc/myapp 8080:80   # Truy cập local
kubectl apply -f .               # Apply toàn bộ manifest trong thư mục
kubectl delete -f deployment.yaml

Helm (trình quản lý package)

Helm đóng gói manifest thành charts có thể tái dùng, dễ template hóa và versioning. (Helm packages manifests into reusable, templateable, versioned charts.)

helm create mychart
helm install myrelease ./mychart
helm upgrade myrelease ./mychart
helm rollback myrelease 1
8. Câu hỏi phỏng vấn (Interview Questions)

❓ Pod vs Container?

Pod là đơn vị triển khai nhỏ nhất — có thể chứa 1+ container dùng chung network/storage. Container chỉ là 1 tiến trình trong pod.

❓ Deployment vs StatefulSet?

Deployment cho app stateless (pod thay thế thoải mái). StatefulSet cho app cần identity ổn định + storage riêng (DB, Kafka).

❓ Service Types?

ClusterIP (nội bộ), NodePort (port cố định trên node), LoadBalancer (cloud LB ra internet). Ingress quản lý routing HTTP.

❓ Rolling update hoạt động thế nào?

Deployment tạo ReplicaSet mới, tăng dần pod mới và giảm pod cũ theo maxUnavailable/maxSurge — không downtime.

❓ Làm sao scale tự động?

HPA scale replica theo CPU/memory/custom metrics; Cluster Autoscaler thêm node; VPA chỉnh resource requests.

❓ Khác biệt Docker vs K8s?

Docker chạy đơn container. K8s điều phối nhiều container trên nhiều node — tự heal, scale, rolling update, service discovery.
