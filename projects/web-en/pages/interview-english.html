🎯 Key Vocabulary

Q: Can you explain OOP principles?
"Object-Oriented Programming has four main principles. First, Encapsulation means hiding internal data and only exposing public methods. Second, Inheritance allows a class to reuse fields and methods from a parent class. Third, Polymorphism enables a single method to behave differently based on the object. Fourth, Abstraction hides implementation details and shows only essential features."
Q: What is the difference between an Interface and an Abstract Class?
"An interface defines a contract — it only declares methods (and default methods since Java 8). A class can implement multiple interfaces. An abstract class can have both abstract and concrete methods, can hold state with fields, and a class can only extend one abstract class. Use interfaces for defining behavior, abstract classes for sharing common code."

🎯 Key Vocabulary

Q: What is Dependency Injection?
"Dependency Injection is a design pattern where dependencies are provided to an object rather than the object creating them itself. The Spring IoC container manages this. Constructor injection is the recommended approach because it makes dependencies explicit, enables immutability, and simplifies testing. Instead of using 'new' keyword, we let the framework inject the required beans."
Q: Can you explain the difference between PUT and PATCH?
"PUT is used to update an entire resource — you send the full object. PATCH is for partial updates — you only send the fields you want to change. PUT is idempotent, meaning calling it multiple times produces the same result. PATCH is generally not idempotent. For example, if a user has 10 fields, PUT requires all 10, but PATCH only needs the fields that changed."

🎯 Key Vocabulary

Q: What is the N+1 problem in Hibernate?
"The N+1 problem occurs when you fetch a list of N parent entities and each one triggers an additional query for its associated children. So you end up with 1 query for the parents plus N queries for the children. We can solve it using JOIN FETCH in JPQL, which loads everything in a single query. Another approach is enabling batch fetching or using DTO projections."
Q: How do microservices communicate?
"There are two main patterns: synchronous and asynchronous. For synchronous communication, services use REST or gRPC. For asynchronous, they use message brokers like Kafka or RabbitMQ. I prefer async communication for decoupling — for example, when an order is created, the order service emits an event to Kafka, and other services consume it independently."

Q: Tell me about a challenging project you worked on.
"In my recent project, I built an order management system using Spring Boot and microservices. The biggest challenge was handling the N+1 query problem and ensuring data consistency across services. I solved the N+1 problem by using JOIN FETCH and batch fetching. For consistency, I implemented the Saga pattern with Kafka for event-driven communication. The result was a scalable system that handles thousands of orders per day."
Q: What are your strengths and weaknesses?
"My main strength is my strong foundation in Java and Spring Boot. I write clean, testable code with proper exception handling and validation. I'm also good at debugging — I can analyze logs, use profilers, and optimize performance. My weakness is that I sometimes spend too much time on code perfection. I'm learning to balance quality with delivery speed by focusing on critical paths first."
